# 专注模式：网页先备场，空格 / 播放键才加载

> 状态（2026-10-21）：已落地并通过视频、HTML、混合项目验证。

## 1. 问题

网页 iframe 在进入专注模式时就会加载并自动播放，导致：

- 用户想按空格「开始」时，实际执行的是「暂停」；
- 网页已经播到中途，无法从第一帧开始录屏；
- 多个网页起跑时间不一致。

视频的逻辑是「进入专注 → 按空格/播放键 → 从 0 同步起播」，网页需要对标这套行为。

## 2. 行为

| 操作 | 纯 HTML / 混合项目 | 纯视频项目 |
|---|---|---|
| 进入专注 | **卸载全部 HTML iframe**，显示黑场 + 底部提示「按空格或点右下角 ▶ 开始（将加载全部页面）」；视频/BGM 暂停 | 原逻辑不变 |
| 空格 / F / 右下角 ▶ | 挂载全部 iframe（带 `oc_hold=1`）→ 等运行时 ready（12 秒兜底）→ 统一 `play`；视频/BGM 归零同帧起播 | 从头循环播放 |
| 播放中再按空格 / ▶ | 网页冻结、视频暂停（保留进度），画面逐像素不变 | 暂停 |
| 暂停后再按 | 网页与视频从暂停处继续 | 继续 |
| R | 视频归零、网页卸载回黑场，等下一次开始重新加载 | 原逻辑：归零并保持暂停 |
| 退出专注 | 恢复挂载 iframe；若退出时仍是备场态，则重载并自动播放，回到 studio 行为 | 原逻辑 |

混合项目走 HTML 分支：网页加载 + 视频归零在同一次「开始」里完成。

## 3. 实现

- `video-wall.tsx`
  - `focusStage: 'idle' | 'loading' | 'playing' | 'paused'`；
  - `focusSuspended`：true 时卡片不挂载 iframe；
  - `suspendFocusHtml()`：进入专注/按 R 时卸载 iframe、清 ready 集合、暂停视频；
  - `startFocusLoad()`：挂载 iframe + `htmlReload { hold: true }`，等 ready；
  - `startFocusPlayback()`：广播统一 `play` + `restartAndPlay` 视频/BGM；
  - ready 收齐（或 12 秒）后自动开演；迟到的 ready 会补发 `play`；
  - 退出专注时若之前处于备场态，恢复挂载并 `hold: false` 重载，避免 studio 里白屏。
- `video-card.tsx`
  - 新增 `htmlSuspended`：true 时不渲染 iframe，只铺一层黑底，直接停止页面网络与动画。
- 专注模式底部提示与右下角按钮文案随阶段变化：备场 → 加载中 → 播放/暂停。

## 4. 实测（2026-10-21，1600×900，`html-test` 4 个 HTML）

| 检查 | 结果 |
|---|---|
| 进入专注 1.2s 后 iframe 数 | **0**（完全没加载） |
| 再等 2.2s | 仍为 0，确认不会偷偷加载 |
| 按空格后 | 4 个 iframe 挂载，`src` 全部 `oc_hold=1`，提示「页面加载中…」 |
| 加载完成后 | 4 个页面同帧开演，按钮变「暂停全部内容」 |
| 播放中两帧 | 37.192% 像素变化 |
| 暂停后两帧 | **0.000%** 像素变化 |
| 按 R | iframe 回到 0，提示重新出现，视频归零 |
| 退出专注 | 顶栏恢复，4 个 iframe 重新挂载 |
| 纯视频项目 | 空格开始 4 路视频、再按暂停，行为不变 |
| studio 同步开始 / 暂停 / 继续 / 录制舞台 | 全部正常，未受影响 |

## 5. 边界

- 第一次按开始需要等页面加载（Spline/Three CDN 可能数秒），这是「按需加载」的代价；加载期间 iframe 带 `hold=1`，不会提前播放。
- 超过 12 秒仍未 ready 会强制开演，迟到页面 ready 后补发 `play`。
- 专注模式仍显示每张卡的标题/信息行（沿用现有设置）；需要完全干净的画面请用顶栏「录制」舞台。
- 底部提示与右下角按钮在开始前会入镜；如果要从黑场开始录，请先开始 OBS 录制再按空格，或从录制舞台走。
