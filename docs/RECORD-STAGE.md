# 录制舞台：16:9 / 9:16 无间隙 + 高质量录制

> 状态（2026-10-21）：Phase 2 录制舞台、Phase 3 应用内录屏、Phase 4 清晰度与标签/竖屏/停顿剪辑均已落地；真实项目验证通过。

## 1. 解决什么问题

Phase 1 解决了"页面能暂停/继续/重来"，但录屏画面里仍有管理 UI：顶栏、侧栏、文件信息行、HTML 角标、卡片圆角与间隙、提示词/水印层。用户拿 OBS 录窗口时还需要手动裁切，且 4 路内容起跑不同步。

录制舞台把"工作台"切换成"成品画布"：只留内容，固定 16:9，倒计时后视频与 HTML 同时开演。

## 2. 使用流程

1. 顶栏点「录制」（无内容时禁用）。
2. 请求标签页捕获；授权后进入舞台（不请求全屏，捕获 API 会退出全屏）。
3. 有 HTML 时先显示「页面备场中」：全部 iframe 以 `oc_hold=1` 重载，等运行时报告 ready；12 秒未齐则强制进入倒计时。
4. 显示 3-2-1 倒计时（每秒一跳）。
5. 归零瞬间：
   - 把舞台按物理像素裁到 canvas（成片只含舞台，1:1，无黑边）；
   - HTML：广播统一的 `play`（`at = now + 100ms`），各卡在同一合成帧恢复；
   - 视频 / 背景音乐：`restartAndPlay` 归零后同步起播。
6. 进入 live：遮罩消失，画面只剩内容，录制的是舞台本身。
7. 录制中快捷键：

| 键 | 行为 |
|---|---|
| `Space` | 暂停/继续；默认同步 `MediaRecorder.pause()`，停顿不会进入成片 |
| `A` | 切换 16:9 → 9:16 → 1:1 |
| `L` | 显示/隐藏模型标签 |
| `P` | 开关「停顿剪辑」：关掉后暂停段会以冻结帧保留 |
| `R` | 重来（网页重载、视频归零） |
| `Esc` | 停止录制并下载 |

8. 右上角「停止并保存 · Esc」按钮默认透明，鼠标悬停才显现；悬停 title 会显示实际捕获规格（分辨率/帧率/目标码率）。

## 3. 视觉规则

- 舞台严格按所选比例：16:9 / 9:16 / 1:1，`width: min(100vw, 100vh*W/H)`、`height: min(100vh, 100vw*H/W)`；按 `A` 切换。
- 只渲染已填充内容位，不再显示空位/占位格。
- 紧凑矩阵：≤1 个 → 1 列；≤4 个 → 2 列（4 个正好 2×2）；更多 → 最多 3 列。
- `gap: 0`；`data-record-stage` 上的全局 CSS 去掉卡片圆角、边框与阴影。
- 13 类 UI 全部隐藏：顶栏、侧栏、专注按钮、提示词/署名、水印、信息行、标题、位置编号、HTML/图片角标、单卡暂停按钮、拖拽提示、退出按钮默认透明。
- 卡片内容按所选比例渲染；4 个内容正好铺满，2 个内容时居中留黑。
- 模型标签：录制态把每张卡的标题画在左下角（`L` 开关）；标题为空则不显示。

## 5. 应用内录屏（Phase 3）

点「录制」时浏览器会先请求屏幕捕获：

1. Chrome 通过 `preferCurrentTab` 默认选中当前标签页（也可手动改选）；
2. 授权后进入舞台备场/倒计时，**倒计时归零才裁舞台并开始写数据**，录到的第一帧就是动画起点；
3. 录制中右上角按钮变为「停止并保存 · Esc」（默认透明，悬停才显现）；
4. `Esc` 或点该按钮：停止 MediaRecorder，生成 **MP4（H.264 + AAC）** 并自动下载，文件名 `omnicompare-YYYYMMDD-HHmmss.mp4`；浏览器不支持 H.264/AAC 时回落 WebM；
5. 拒绝授权/浏览器不支持：舞台照常进入，提示「未开启应用内录屏：仍可排练，或用 OBS 捕获本窗口」。

录制态快捷键：

| 键 | 行为 |
|---|---|
| `Space` | HTML 与视频同时暂停 / 继续（默认同步暂停录制器，停顿不入片） |
| `A` | 切换 16:9 / 9:16 / 1:1 |
| `L` | 显示/隐藏模型标签 |
| `P` | 开关「停顿剪辑」 |
| `R` | HTML 重载 + 视频/BGM 归零，从头开始 |
| `Esc` | 停止录制并保存、退出舞台 |

实现：

- `src/lib/screen-recorder.ts`：`requestTabCapture`（10s 超时、失败返回 null；只约束 60fps，不请求 width/height）、`createTabRecorder`（默认 H.264/AAC MP4，按 0.2 bit/像素/帧、20–50Mbps；VP9/Opus WebM 兜底）、`downloadRecording`、`recordingFilename`。
- `video-wall.tsx`：`prepareRecVideo()` 提前挂好隐藏 video；`startStageCanvas()` 把舞台按物理像素裁到 canvas，再用 `canvas.captureStream(60)` + 原标签页音轨组成录制流；`stopRecorder()` 清理 canvas/rAF/音轨；捕获流 `ended` 时自动停止。

注意：

- 需要安全上下文：`localhost` 可以；局域网 `http://192.168.x.x` 浏览器会禁用 `mediaDevices`，此时自动降级到 OBS 方案。
- 标签页音频是否入轨取决于浏览器与共享选项；画面始终捕获。
- 自动下载可能触发浏览器的"允许多个文件下载"提示，允许一次即可。

## 6. 清晰度（Phase 4.1）

结论：清晰度不是靠请求 4K，而是靠 **1:1 物理像素 + 高码率 + 不把黑边录进去**。

实测事实：

- 标签页捕获输出的是**物理像素**：1536×728 CSS × DPR 1.25 → 1920×910 视频，不是 720p。
- `getDisplayMedia` 的 `width`/`height` 只是对已选画面做缩放，不能增加细节；请求 4K 会得到 3840×1820 的放大画面（没有意义）。
- **全屏会被 `getDisplayMedia` 强制退出**，标签页随即缩回 842 高；所以“自动全屏”无效，已移除。
- MediaRecorder 实际码率：VP9 目标 60Mbps 实测约 18Mbps；H.264 目标 15Mbps 实测约 35Mbps，且 MP4 里同时有 `avc1` + `mp4a`（AAC 音轨不丢）。因此默认改为 **H.264/AAC MP4**，WebM 只做兜底。
- **舞台录制改为 canvas 裁剪**：只把舞台区域按物理像素画到 canvas（例如 1618×910），成片就是舞台 1:1，没有黑边、没有整窗缩放。这是本轮解决“不清晰”的关键。
- 目标码率：H.264 按 0.2 bit/像素/帧，20–50Mbps；VP9 回落按 0.25，20–80Mbps。实际码率仍会随画面复杂度浮动。
- 实测真实成片：**1618×910、H.264+AAC、12.6Mbps、5.4 秒 / 8.4MB**，文字边缘锐利，无 toast、无整窗黑边。

边界：

- 输出分辨率 = **舞台物理尺寸**。1080p 屏幕窗口模式下约 1618×910；要 1920×1080，需要内容区本身达到 1920×1080（4K 屏、更大窗口或无浏览器 chrome 的窗口），不能靠编码放大。
- 6 个内容 3×2 会在 16:9 舞台内留上下黑边（内容本身 2.67:1）；4 个 2×2 正好铺满。
- 鼠标指针：Chrome 标签页捕获当前忽略 `cursor: 'never'`，录制时把鼠标移到浏览器工具栏/画面外；页面 live 阶段也设了 `cursor: none` 减少干扰。
- 全屏会被捕获 API 退出，不建议按 F11 录；用当前窗口或更大窗口。

## 8. 边界与后续

- 2 个内容时按所选比例居中留黑；4 个是推荐配置。
- 3 个内容为 2 列 × 2 行，右下角留一格黑。
- 录制舞台不显示信息行/提示词/水印；模型标签可按 `L` 显示卡片标题，需要片头字幕建议后期加。
- 应用内录屏依赖浏览器屏幕捕获授权：真实标签页需要你手动点一次"允许"。
- 输出分辨率 = 舞台物理尺寸：1080p 屏幕窗口模式约 1618×910；要 1920×1080 需要内容区本身达到 1920×1080（4K 屏/更大窗口），不能靠编码放大。
- 4K：需要 4K 显示器（或 4K 内容区）；标签页捕获不能超过源像素，无法在 1080p 窗口里凭空录出 4K。
- 编码默认 MP4（H.264+AAC）；H.264/AAC 不可用时回落 WebM（VP9+Opus）。
- 鼠标指针：Chrome 标签页捕获当前忽略 `cursor: 'never'`；录制时把鼠标移到浏览器工具栏/画面外，页面 live 阶段也设了 `cursor: none`。
- 录制前请把浏览器切到前台：浏览器对后台标签页会把 rAF 限到约 20fps；进入录制时若 `document.hasFocus()` 为 false 会弹一次提醒。
- Safari / macOS 的屏幕捕获行为未实测。
